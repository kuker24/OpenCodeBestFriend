# Taste: Redesign Boundaries & Asset Preservation

Deep reference module for Impeccable.
Adapted from [taste-skill](https://github.com/Leonxlnx/taste-skill) (MIT, Leonxlnx).

## 1. Refinement vs Redesign

- **Refinement (Preserve)**:
  - Scope: fixing styling bugs, improving contrast, adjusting typography, adding missing states, or polishing micro-interactions.
  - Boundary: preserve the existing visual world, brand colors, established copy, routes, and data flows.
  - Do not trigger a concept redesign or replace DESIGN.md for a narrow bug fix or component addition.
- **Redesign (Overhaul)**:
  - Scope: broad visual replacement of a dated, inconsistent, or templated interface when explicitly brief-approved.
  - Boundary: keep product truth, user workflow, features, and native constraints, while establishing a new visual world and replacing DESIGN.md.
  - Never split the difference into a muddy hybrid that satisfies neither the old brand nor the new vision.

## 2. Working with Incumbent Assets

- **Brand Colors & Logos**: Pinned brand tokens must be carried over. If the brand has a primary purple, green, or blue, that color remains the hero accent.
- **Real Imagery & Copy**: Preserve factual statements, pricing numbers, endpoint names, and domain terminology. Never replace accurate technical copy with vague marketing buzzwords.
- **Incremental Upgrades**: When adding a single new page to an established product, inherit the existing system instead of introducing an alien aesthetic dialect.
